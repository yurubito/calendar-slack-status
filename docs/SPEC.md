# 仕様書: カレンダー連動の Slack ステータス・通知切り替え

## 1. 目的
Google カレンダーの「今の予定」に合わせて、Slack の
- ステータス（絵文字・文言・有効期限）
- 通知の一時停止（おやすみモード）
を自動で切り替える。**だれでも、自分のカレンダーと Slack をつなぐだけで使える** ようにする。表示のしかたは各自が画面で変えられる。

Slack 公式の Google カレンダーアプリとの違い: 公式はステータスが「会議中」の1種類で、通知も全部止めるか止めないかの2択。こちらは予定名を出せる・キーワードや予定ごとに決められる・通知をボタン1つで切り替えられる。

## 2. 全体の形
- **Google Apps Script のウェブアプリ** として作る（無料）
  - 「ウェブアプリを使うユーザーとして実行」にして、使う人それぞれの Google アカウントで動く。カレンダーは各自のものを読む
  - 設定は各自の `UserProperties` に保存。ほかの人の設定は見えない
  - 時間のトリガーも各自に作る（初回の「はじめる」ボタンで作成）
- **Slack アプリを1つ** 作り、ワークスペースに入れる
  - 使う人は設定画面の「Slack とつなぐ」から OAuth で許可する → 各自のユーザートークンを `UserProperties` に保存
  - スコープ（ユーザートークン）: `users.profile:read`, `users.profile:write`, `dnd:read`, `dnd:write`
  - アプリのクライアント ID とシークレットは `ScriptProperties` に置く。コード・リポジトリ・ログに書かない
- 5分おきに実行して、今の予定に合わせて切り替える

## 3. 設定画面（ウェブアプリ・スマホでも使える）
- デザインは Soft Flow（`docs/design/soft-flow.md`）。**ヘッダーにナビゲーションを置き、ページを分ける**（2026-10-25 オーナー決定）。ページ: **表示モード**（3-1・3-2）／**キーワード登録**（3-3）／今日の予定（3-4）／接続（Slack とつなぐ・3-5）。ホームのページは置かない。最初に開くのは表示モード（2026-10-25 オーナーが使ってみて決定）
- スマホはヘッダーのメニューを横スクロールのタブにする。キーワード登録はスマホで1件ずつのカード（開け閉めできる）、PC で表
- 画面は Slack の中には出ない。ブラウザで開くウェブアプリで、スマホでは Slack のリンクやブックマークから開く
### 3-1. 通知とスイッチ（表示モードのページの上部）
- **「通知を止める」はスイッチ**。ON にするとすぐ Slack のおやすみモードに入り、OFF にすると再開する
  - ON にするとき「30分／1時間／今の予定が終わるまで／自分で再開するまで」を選べる
- **「自動で切り替える」のスイッチ**（全体の ON/OFF）。OFF にすると、ステータスも通知も自動では変えない

### 3-2. ステータスへの反映方式（表示モードのページのカード）
次の3つから1つ選ぶ。
1. **予定名**（初期設定）。例: 予定「授業：数学」→ ステータス「授業：数学」
2. **カスタム**。選ぶと「ステータス名」の入力欄が出る（例:「予定あり」）。予定名を出したくない人向け
3. **なし**（ステータスは変えず、通知の切り替えだけ使う）

共通の設定: 絵文字（初期値 :calendar:）、予定中は通知を止めるか（スイッチ・初期値: 止めない）。
- ステータスに付ける接頭辞と文字数の上限の設定項目は置かない（2026-10-25 オーナー）。Slack の上限 100文字には常に合わせて切る

### 3-3. キーワード登録（上の反映方式より優先）
表で何行でも足せる。上から順に照合し、最初に当たった行を使う。

| 項目 | 例 |
|---|---|
| キーワード（予定名に含む文字。完全一致も選べる） | `授業` |
| ステータス名（空なら予定名をそのまま出す。`{title}` で予定名を差し込める） | `📚 {title}` |
| 絵文字 | :books: |
| 通知を止める | する／しない |
| この予定を無視する | する／しない |

- 例: キーワード「睡眠」→ ステータス名「おやすみ中」・通知を止める。キーワード「本業」→ ステータス名「別の用事中」（予定名を隠す）
- 並べ替え・削除・一時的に無効、ができる。無効にした行は暗く表示する
- PC の表では、チェックボックスの横に項目名を重ねて書かない（見出しで分かるため）

### 3-4. 予定ごとの設定
- 今日〜1週間先の予定の一覧を出し、**1件ずつ上書きできる**（ステータス名・絵文字・通知・無視）
- 繰り返しの予定は「この回だけ／毎回」を選べる
- 優先順位: 予定ごとの設定 ＞ キーワード登録 ＞ ステータスへの反映方式

### 3-5. その他の設定
- 読むカレンダー（自分のカレンダーの中から複数選べる。初期値はメインのカレンダー）
- 無視する予定: 終日の予定（初期値: 無視）、「空き時間」の予定（初期値: 無視）、辞退した予定（常に無視）
- 予定が重なったとき: 「後から始まった予定」か「ルールの上の行に当たる予定」かを選べる
- 予定の前後の余白（例: 予定の5分前から切り替える）
- 設定の書き出し・読み込み（JSON）。ほかの人に自分の設定を渡せる

## 4. 自動で切り替える動き
5分ごと（使う人ごとのトリガー）に次を行う。
1. 「自動で切り替える」が OFF なら何もしない
2. 今の時刻にかかっている予定を取り、3-3〜3-5 の順で使う設定を決める
3. ステータスを設定する。有効期限は予定の終わり
4. 「通知を止める」なら、予定の終わりまでおやすみモードにする
5. **手で付けたステータスは上書きしない。** スクリプトが付けたステータスを覚えておき、今のステータスと違えば手で変えたとみなして触らない
6. 前回と同じ内容なら Slack の API を呼ばない（回数を減らす）
7. 予定が終わったら何もしない（ステータスは期限で消える）。通知のボタンで「自分で再開するまで」を選んでいるときは、自動では再開しない

## 5. 失敗したとき
- Slack の API がエラーを返したら、ログに残して次の回に任せる
- トークンが無効（`invalid_auth` など）のときは、設定画面の上に「Slack とつなぎ直してください」と出す。本人へのメールは1日1回まで
- Google 側の上限（トリガーの実行時間など）に近づいたら、ログに残す

## 6. やらないこと
- カレンダーの予定の作成・変更・削除（読むだけ）
- Slack へのメッセージの投稿
- ほかの人のステータス・設定の変更

## 7. 開発のしかた
- 進め方と技術の決まりは [AGENTS.md](../AGENTS.md)

## 8. テストで確かめること（Codex への依頼に含める）
- キーワードの照合: 含む／完全一致、上から順、無効にした行は飛ばす
- 優先順位: 予定ごとの設定 ＞ キーワード登録 ＞ ステータスへの反映方式
- `{title}` の差し込み、100文字で切る、絵文字の初期値
- 終日・空き時間・辞退した予定を無視する
- 予定が重なったときの選び方（2通り）
- 手で付けたステータスを上書きしない
- 前回と同じなら API を呼ばない
- 「自分で再開するまで」を選んでいるときは自動で再開しない

## 9. 〔要確認〕
- 導入先の Slack ワークスペースで、アプリを入れるのに管理者の承認が要るか
- Google Workspace の設定で、Apps Script のウェブアプリを公開できるか・外部（Slack）への通信が止められていないか
- 複数のワークスペースに配るなら、Slack アプリの公開配布の設定が要る
